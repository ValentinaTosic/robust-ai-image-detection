## Project Overview

AI image detectors are often evaluated on generators that were also seen during
training. This can give an overly optimistic estimate of how well they perform
on images generated by new or unseen models.

This project focuses on a stricter evaluation setting: whether a detector can
generalize to AI-generated images from a generator that was not present during
training.

The main goal is to compare different architectures and investigate which
approaches are more robust to unseen generative models.


## Research questions

- **RQ1 — Baseline:** How well do models distinguish real from AI-generated
  images when all generators are present in the training data?

- **RQ2 — Generalization:** How much does performance decrease when the model
  is evaluated on a generator that was not seen during training?

- **RQ3 — Architecture:** How do different architectures compare in their
  ability to generalize to unseen generators?

- **RQ4 — Frequency information:** Does adding frequency-domain information
  improve generalization to unseen generators?

## Dataset

We use the [Tiny-GenImage dataset](https://www.kaggle.com/datasets/yangsangtai/tiny-genimage), a smaller version of the GenImage benchmark designed for more manageable experimentation.

The dataset contains real images from ImageNet and AI-generated images produced by multiple generative models. For this project, we use the following seven AI generators:

- BigGAN
- GLIDE
- VQDM
- Stable Diffusion v1.5
- ADM
- Midjourney
- Wukong

The original GenImage benchmark also includes Stable Diffusion v1.4, but it is not available in the dataset version used for this project and is therefore excluded from the experiments.

### Dataset Size

The current configuration uses 1,000 AI-generated images per generator:

- **AI-generated:** 7,000 images
- **Real:** 7,000 images
- **Total:** 14,000 images

The real images are sampled from the available real-image pools and are
balanced against the AI-generated images.

### Dataset Splits

The standard experiment uses a stratified:

- **70% training**
- **15% validation**
- **15% test**

split.

This results in:

| Split | AI | Real | Total |
|---|---:|---:|---:|
| Train | 4,900 | 4,900 | 9,800 |
| Validation | 1,050 | 1,050 | 2,100 |
| Test | 1,050 | 1,050 | 2,100 |
| **Total** | **7,000** | **7,000** | **14,000** |

Each generator is proportionally represented across the standard splits.

## Dataset Preprocessing

All images are processed using the same pipeline regardless of their source:

1. Resize to `224 × 224`
2. Convert to RGB
3. Remove image metadata
4. Re-encode as JPEG with consistent quality

This preprocessing is applied equally to real and AI-generated images.

## Dataset Bias Prevention

A potential issue in AI image detection datasets is that models can learn
properties of the data sources instead of actual AI-generation artifacts.

For example, if AI images are PNG files with a fixed resolution while real
images are JPEG files with varying resolutions, a model could distinguish the
classes using these properties alone.

To reduce this risk, resolution, color mode, metadata, and compression are
standardized across all sources before training.

The dataset analysis notebook also checks for differences in image statistics,
duplicate images, and potential cross-source similarities.
